# Portfolio Site Design Brief

## Objective
Create a polished, deployable personal portfolio for a software developer. The repository at `C:\solo\portfolio` is currently empty, so build a complete framework-free static site with no dependency-install or build step. It must work locally and deploy to Vercel's free Hobby plan from a GitHub repository.

## Audience
Hiring managers, engineering leads, collaborators, and prospective clients who want to quickly understand the developer's strengths, selected work, and how to get in touch.

## Aesthetic direction
An editorial developer portfolio with a warm, near-black canvas and sharp citron-lime accents. Make it feel like a considered independent studio, not a generic SaaS landing page. Use large typographic hierarchy, restrained grid lines, generous negative space, and one memorable custom-built visual motif: a CSS-rendered orbital/coordinate system framing the hero identity. The interface should feel tactile and quietly confident.

## Content structure
1. Slim top navigation with identity wordmark, section links, and a visible availability/contact action.
2. Hero: eyebrow availability/status, large developer-focused headline, brief introductory copy, primary project CTA, secondary contact link, and distinctive orbital visual.
3. Compact proof strip with editable experience/discipline/location details.
4. Selected-work section with three visually distinct project cards, clear roles, technologies, and editable descriptions. Use locally made CSS artwork rather than external service imagery.
5. About section with concise human introduction and a few editable focus areas.
6. Contact callout with mailto action and social/profile links.
7. Footer with copyright and back-to-top affordance.

Use clearly replaceable sample copy rather than inventing the site owner's identity, credentials, clients, or actual project history. Mark editable personal details in the README.

## Typography
Use a distinctive but dependable system-font pairing: strong compact sans-serif headings with a neutral readable system sans-serif body. Avoid loading remote font services so the page works without third-party requests.

## Color and texture
- Page background: deep charcoal, approximately `#11120f`.
- Surface/panel: subtly lighter charcoal, approximately `#1a1b17`.
- Primary text: warm off-white, approximately `#f2f1e8`.
- Secondary text: subdued warm gray.
- Accent: bright citron/lime, approximately `#c9f31d`.
- Fine separators and decorative grid: low-contrast olive/gray.
Ensure readable contrast and visible keyboard focus.

## Responsive behavior and interaction
Design mobile-first and verify at a narrow viewport and desktop. Keep navigation usable on small screens; avoid horizontal overflow. Provide a small accessible menu only if needed. Implement a working mobile navigation if the layout requires it. Add subtle, motion-safe hover/focus transitions and a reduced-motion fallback. No fake form submission or backend; use a working `mailto:` contact link.

## Technical and deployment constraints
- Output path: `C:\solo\portfolio`.
- Prefer `index.html`, `styles.css`, and `script.js` with semantic HTML, accessible controls, and no dependencies or build step.
- Include a concise `README.md` with local preview steps, editable-content guidance, and exact GitHub-to-Vercel deployment instructions for a static project (Framework Preset: Other; no build command; output directory: `.`).
- No external image services and no required remote assets.
- Keep any Vercel configuration minimal; do not introduce a framework only for deployment.
- Do not overwrite or remove any existing unrelated files.

## Images
No photographic imagery is needed. Draw visual accents with CSS and simple inline geometric shapes; do not reference external image URLs.
